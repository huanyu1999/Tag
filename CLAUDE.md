# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Firmware for the **"Label" (标签 = TAG)** node of a Railroad Active Warning Device — a UWB
proximity-warning system. A worker carries this tag; trackside/train **anchors** broadcast,
and the tag ranges against them via two-way ranging (TWR). When an anchor comes within
`MIN_DISTANCE` the tag fires its red LED + buzzer; losing all anchors for 60 cycles raises a
"lost connection" warning (yellow LED).

- **MCU:** STM32F103CBTx (Cortex-M3, 128 KB flash), HSE + PLL → 72 MHz.
- **Radio:** Decawave **DW1000** UWB transceiver over SPI1 (DMA), CS = PA4 (software-driven).
- **Peripheral init** is generated by STM32CubeMX from `Label.ioc`.

## Build / Flash

There is no Makefile and no host test suite — this is bare-metal firmware built with **Keil
MDK-ARM (µVision 5)**.

- Open `MDK-ARM/Label.uvprojx` in µVision; Build (F7), Flash via ST-Link (F8).
- CLI build (if Keil is installed): `"C:\Keil_v5\UV4\UV4.exe" -b MDK-ARM\Label.uvprojx -o build_log.txt`
- Project define: `USE_HAL_DRIVER, STM32F103xB`. The single Keil target is `Label`.
- `keilkilll.bat` (untracked) deletes Keil intermediate/output dirs for a clean rebuild.
- After editing `Label.ioc` in CubeMX and regenerating, the Keil file list / `Core/Src` HAL
  init files change — re-check that hand-written code still lives inside `/* USER CODE BEGIN/END */`
  blocks (everything outside them is overwritten on regeneration).

## Architecture

Layered, bottom-up:

1. **`Core/Src`, `Core/Inc`** — CubeMX-generated HAL peripheral setup (`main.c`, `gpio/spi/usart/adc/tim/dma.c`). `main()` inits peripherals, then calls `DW1000_init()` and `dw_main()`; it never returns to the `while(1)` below.
2. **`Core/platform`** — hardware abstraction bridging the Decawave driver to STM32 HAL: `deca_spi.c` (SPI+DMA transfers), `port.c` (reset/IRQ/LED/buzzer/`portGetTickCnt`), `deca_sleep.c`, `deca_mutex.c`.
3. **`Core/decadriver`** — Decawave DW1000 device driver (`dwt_*` API). Treat as vendor code.
4. **`Core/application`** — the UWB application:
   - `dw_main.c` — `DW1000_init()` (RF config, antenna delay, role, callbacks) and `dw_main()` (the main loop: run state machine, then on a good range apply Kalman filter and print results over UART-DMA).
   - `instance_tag.c` — the **tag TWR state machine** (`tag_app()`), the only role compiled into this project.
   - `instance.h` — **central config + protocol header**: tunables, message frame byte-offset map, function codes, the `instStatus` state enum, and all shared `extern` globals.
   - `instance_anchor.c` — anchor state machine. **Present but NOT in the Keil build** (the `Dw1000/Application` group only lists `dw_main.c` + `instance_tag.c`). Useful as the protocol counterpart reference.
5. **`Core/kalmanfilter`** — scalar Kalman filter applied per `[anchor][tag]` distance series.

### TWR protocol & timing (the core of the system)

One ranging cycle: tag sends **POLL** → each anchor replies **RESP** (which also carries the
previous cycle's computed distance) → tag sends **FINAL** containing the POLL-tx / RESP-rx /
FINAL-tx timestamps so the anchor computes time-of-flight. The tag displays the distance it
reads back out of each RESP. Message layouts are defined purely by the `*_IDX` byte offsets in
`instance.h` — edit those tables, not magic numbers in the `.c` files.

Multi-tag collision avoidance uses a slot / super-frame scheme: `next_period_time`,
`inst_one_slot_time * inst_slot_number`, plus a `tagSleepCorrection_ms` broadcast by the
time-sync anchor (the anchor whose group-ID high bit is set, i.e. A0). All the per-data-rate
timing constants (`*_110K` / `*_850K` / `*_6P8M`) come in matched sets — change them together.

### Key conventions & gotchas

- **Role is hardcoded** to `TAG` inside `DW1000_init()` (`instance_mode = TAG; dev_id = TAG_ID` = `0x18`). There is no board EEPROM (`USE_EEPROM = 0`), so antenna delay / TX power / ID all come from `#define`s, not runtime config. The `$`-prefixed UART command parser and EEPROM paths are commented out.
- **Board variant** is selected by a single `#define` near the top of `instance.h` (`ULM1` / `LD150` / `LD_PA`), which picks `ANT_DLY` and `TX_POWER`. Currently `LD150`.
- **RF profile** is chosen by indexing `uwb_config_channel5[]` in `DW1000_init()` (currently `[2]` = channel 5, 64 MHz PRF, preamble 1024, 850 kbps). Changing the index auto-selects the matching timeout/interval constant set.
- **Shared EXTI0 IRQ:** DW1000 IRQ is on PB0 and RSTn on PA0 — both map to `EXTI0`. `setup_DW1000RSTnIRQ()` disables the line, so `DW1000_init()` deliberately re-enables `EXTI0_IRQn` at its very end. Don't remove that.
- **SPI completion flags:** `dw1000_spiDmaCpltFlag` / `dw1000_spiDmaBusyFlag` are set in `HAL_SPI_TxCpltCallback` / `HAL_SPI_TxRxCpltCallback` (in `dw_main.c`), which also raise CS (PA4). The TWR state machine busy-waits on `tx_status`/`rx_status` flags that the `dwt_*` callbacks flip.
- **Alarm semantics** (driven from the TIM2 period callback in `main.c`): `distance_flag` = nearest anchor closer than `MIN_DISTANCE` → red LED + buzzer; `lost_flag` = 60 consecutive `RANGE_ERROR` cycles → yellow LED, buzzer off. `distance_report[]` is in millimetres (printed `/1000` as metres).
- **Output** goes out USART1 via `printf_use_dma()` (non-blocking). ADC1 + TIM3 periodically sample battery voltage (`Real_value`).
- Source comments are in Chinese; match that style when editing application code.

### In-progress: DW1000 → DW3000 dual-target (branch `dw1000-dw3000-dual-target`)

`Core/Dw3000/` holds a parallel DW3000 driver (`decadriver/`) and platform layer, separate from
the active `Core/decadriver` + `Core/platform` (DW1000). The DW3000 tree is **not yet referenced
by the Keil project** — the refactor to support both radios from one codebase is ongoing. When
touching driver/platform code, be explicit about which target (DW1000 vs DW3000) you mean, since
the two trees define overlapping `dwt_*` / `port_*` symbols.
